# NORA — Студентський ШІ-асистент університету

Командний проєкт зі створення інтелектуального університетського помічника **NORA**, який допомагає студентам швидко знаходити навчальну, адміністративну та побутову інформацію.

## Основні можливості ШІ NORA

* **Персоналізація:** профіль студента з прив'язкою до курсу, спеціальності та академічної групи.
* **Навчання та розклад:** розклад занять (викладач, аудиторія, час), дати сесій, іспитів, заліків, дедлайнів і канікул, а також пошук силабусів, методичок і підручників.
* **Університет і факультет:** контакти деканату, кафедр, викладачів, розташування корпусів та аудиторій, пояснення правил університету.
* **Студентське життя та документи:** поселення в гуртожиток і пошук житла, оформлення стипендії, оплата контракту, бібліотечний квиток, студентські події, знижки, стажування та програми обміну (Erasmus).

## Архітектура та технологічний стек

```text
Frontend (React + React Router)
       ↓
Backend REST API (Node.js + Express)
       ↓
Firebase Auth / Firestore  +  AI API
```

> [!IMPORTANT]
> Усі операції з даними (CRUD користувачів, профілів, історії чатів) виконуються виключно через **Node.js backend** із серверною перевіркою токенів через **Firebase Admin SDK**, а не напряму з клієнта.

## Розподіл ролей у команді

* **Студент 1 — Backend / Node.js:** сервер на Express, архітектура REST API (`Routes`, `Controllers`, `Services`, `Middleware`), валідація запитів, обробка помилок та серверний CRUD.
* **Студент 2 — AI Integration:** підключення AI SDK/API через `.env`, налаштування системних інструкцій (`system instruction`), ендпоінт `POST /api/chat`, інтеграція університетської бази знань як контексту.
* **Студент 3 — Firebase / Database & Auth:** структура колекцій Firestore (`users`, `profiles`, `chats`, `messages`), авторизація через Email/Password і Google Sign-In, інтеграція Firebase Admin SDK.
* **Студент 4 — Frontend / React:** клієнтський застосунок, захищені маршрути, сторінки `Login`, `Registration`, `Forgot Password`, `Home`, `Dashboard`, `Chat UI`, `Profile`, історія чатів, категорії та пошук.
* **Студент 5 — UI/UX:** розробка User Flow, Sitemap, Wireframes та Design System у Figma, адаптивні макети (Desktop/Mobile), проведення Usability-тестування зі студентами.

## План розробки (7 місяців)

1. **1 місяць — Основи:** опанування базових технологій кожним учасником та перші тестові прототипи.
2. **2 місяць — Підготовка:** поглиблення стеків, структурування REST API, дизайн основних екранів і налаштування авторизації.
3. **3 місяць — Перше об'єднання:** інтеграція `Backend + Firebase + AI` в єдину серверну систему та початок зв'язки `Frontend → Backend API`.
4. **4 місяць — Повна інтеграція:** повний цикл `React → Node.js → Firebase / AI → Node.js → React` із підключенням бази даних університету.
5. **5 місяць — MVP:** повністю робочий основний сценарій користувача від реєстрації до діалогу зі ШІ.
6. **6 місяць — Стабілізація:** тестування, виправлення багів, безпека (`rate limiting`, перевірка прав доступу), оптимізація та деплой у production.
7. **7 місяць — Розширення:** додавання нових функцій та AI Tools, фінальна презентація та демо.

## Правила командної роботи з Git

1. Перед початком роботи оновіть локальну гілку `main`: `git pull origin main`.
2. Створюйте окрему гілку під кожне завдання: `git switch -c feat/назва-функції` або `git switch -c fix/назва-виправлення`.
3. Не комітьте секретні ключі, файли `.env` або ключі сервісних акаунтів Firebase (`*serviceAccountKey*.json`).
4. Відкривайте **Pull Request** у `main` і прив'язуйте його до відповідної картки на канбан-дошці проєкту.
